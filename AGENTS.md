# AGENTS.md

Instructions for AI coding agents working in this repository.

## Rules

1. **Never run git commands that change anything, unless the user explicitly asks for that exact action in their current message.** This includes `add`, `commit`, `amend`, `reset`, `checkout`/`switch`, `stash`, `rebase`, `merge`, `tag`, `push` and branch create/delete. It also covers anything that changes GitHub: `gh pr create/merge/close`, `gh api` writes, releases and repository settings.
   - Read-only commands are fine: `git status`, `git log`, `git diff`, `git show`, `git branch --list`, `gh pr view`.
   - A question about the release flow ("then we push and tag?") is a question, not an instruction.
   - Leave changes uncommitted in the working tree. The maintainer reviews, commits and pushes.
2. **No AI attribution.** Never add `Co-Authored-By`, "Generated with…" or similar lines to commits, PRs, tags or files.
3. **Pushing a `v*` tag deploys the live site.** Never create or push tags.
4. If an action is blocked or fails, stop and report it. Don't substitute a different or more destructive action.

## Project

Personal blog of Nick Pateman, served at https://www.npsoftware.co.uk. It's a plain Jekyll 4 site with no plugins.

- `_posts/` holds the posts, written in Markdown (kramdown). The permalink is `/:title/`, taken from the filename, so **renaming a post file changes its live URL**.
- `_layouts/` and `_includes/` hold the templates. Every layout goes through `compress.html`, which minifies the HTML.
- `assets/css/main.css` and `assets/js/main.js` are hand-edited, with no build step. The original Stylus/gulp sources were removed because they were years out of date.
- `feed.xml`, `sitemap.xml`, `search.json` and `tags.html` are generated by hand-written Liquid, not by plugins.
- `_config.yml` sets `timezone: Etc/UTC` so local builds match CI. Keep it, or post timestamps will differ between machines.
- `initpost.sh -c <title>` creates a new post skeleton.

## Build

The supported environment is WSL2 Ubuntu with the distro's Ruby. See `README.md` for the full setup.

```bash
bundle config set --local path vendor/bundle   # once per clone
bundle install
bundle exec jekyll build                       # output in _site/
bundle exec jekyll serve --force_polling       # http://127.0.0.1:4000
```

- Bundler is installed with `gem install --user-install bundler`, so add `$(ruby -e "print Gem.user_dir")/bin` to `PATH` if `bundle` isn't found.
- When invoking from Windows, run through WSL: `wsl.exe -e bash -lc 'cd /mnt/e/Source/GitHub/npsoftware.co.uk && ...'`.
- A build should finish with no warnings. Treat new Liquid or deprecation warnings as something to fix.
- The only direct dependency is `jekyll` (`~> 4.4`). Commit `Gemfile.lock`, and keep its `x86_64-linux` platform entries because CI needs them.

## CI/CD

- `.github/workflows/build.yml` builds every push to any branch and every PR. It never deploys.
- `.github/workflows/deploy.yml` deploys only from `v*` tags on commits in `master`, for example by publishing a GitHub release. It checks the tag is on `master`, runs the Jekyll build, then `aws s3 sync --delete` and a CloudFront invalidation. A tag that isn't on `master` fails before anything is uploaded.
- Both use Ruby 3.4 through `ruby/setup-ruby` with `bundler-cache`. The AWS credentials, bucket and distribution ID are secrets, and the deploy job runs in the `production` environment.
- There is no Travis, Heroku or GitHub Pages deployment. Don't re-add a `CNAME`, `Procfile` or `config.ru`.
